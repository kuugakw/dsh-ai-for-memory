# 常见问题

> 返回 [主 README](../README.md)。

**AI for Memory 是什么？**

面向 DSH 的项目级记忆插件。它把项目过程中产生的事实、约定、错误修复、决策和对话上下文分开保存、按需检索，并支持清理前存档和恢复；不是通用聊天记录收藏夹。

**看不到工具或面板？**

确认 bundle 已安装，并重新加载插件；检查面板是否被 DSH 的布局设置隐藏。

**RAG 打不开？**

RAG 需要同时配置 Embedding 模型和 Rerank 模型。只有其中一个时，保存挂载会被拒绝。

**SQL 查询不可用？**

SQL 通道和 SQLite 镜像需要运行时的 `node:sqlite`。插件要求 **Node 22.15+**，该版本已内置 `node:sqlite` 与 zstd；更旧的运行时不再支持。

**清空上下文后还能找回吗？**

清理前会先写 `contexts/` 存档，之后用 `aim_context action=restore context_id=...` 调回。恢复默认只注入预算内的最近轮次，完整存档仍在磁盘上。

**为什么知识库里有黄标？**

那是模型自述，尚未确认。确认无误后在面板点「确认这条」即可；不要直接把黄标内容当成项目事实。

**跨对话检索会污染本对话权重吗？**

不会。跨对话命中不写入调用方使用日志，也不套调用方权重；每个文档的权重只属于它所在的 store。

**保存设置后要手动重载吗？**

不需要。保存会自动重载并刷新面板；如果还在重载，会显示提示并稍后自动刷新。

**历史对话打不开，提示 `stored log is corrupt` / `SessionFormatError` 怎么办？**

这是 DSH 自己的会话日志坏了，不是记忆目录的问题：一条事件不满足 v4 会话格式，DSH 就会拒绝整份 `session.v4.jsonl.zstd`。用 `aim_repair action=scan deep=true` 找到它，再 `aim_repair action=repair session=<id>` 预演、加 `apply=true` 写回；面板「诊断 → 会话日志体检与修复」也有同样的入口。修复前会自动备份，修完重新打开该对话即可。写回前会按内容指纹复核：如果该对话仍在生成（当前标签页或另一个标签页），或文件在规划期间被追加，就会放弃写回并提示冲突，不会覆盖新事件。旧版插件写入的 `developer/message` 请求锚点会被改写成 `user/message` 便条，历史一条不丢。若日志结构正常但物理体积异常，用 `action=compact` 重排 zstd 帧（事件不变）。
