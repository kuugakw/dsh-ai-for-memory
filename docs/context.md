# 上下文与自动行为

> 返回 [主 README](../README.md)。

> 想看完整的清理机制——触发条件、相似度打分公式、压力硬重置、存档与恢复、调参与边界——见 [上下文清理机制](context-clearing.md)。本文其余部分偏重各项自动行为的行为约定。

## 自动行为

### 自动整理

`autoEnabled` 默认**关闭**。打开后，每个 `turn/end` 检查轮次，每次模型请求前检查一次上下文占用：

- 每 `autoEveryRounds` 轮（默认 5）触发；或
- 上下文占用达到 `contextUsagePercent`（默认 70%）触发。

两个条件任一满足，本轮只整理一次：

1. 生成轮次摘要，写入过程记录；
2. 执行归档；
3. 如果 `autoKnowledge !== false`，顺带提炼知识。

**上下文超过 `contextUsagePercent` 时走硬重置**：

- DSH 的真实任务是“一个请求 + 很多工具步骤”，所以硬重置按**步骤**而不是只按轮次工作：在任务进行中的任意一次模型请求前都会检查占用，超阈值就清出旧的步骤，注入续接包，然后**继续同一个任务**，不需要等这一轮结束；
- 一次整段替换：从当前轮第一个 assistant 节点开始，一直替换到“保留段”起点；当前轮的用户请求和随请求到达的 runtime/skill/time 提示原样保留，模型和面板都还看得到任务是什么；
- 保留段 = 最近 `keepRecentTurns` 轮（默认 2）+ 当前轮最近 `keepRecentSteps` 个步骤（默认 3）；切割点只落在步骤边界（上一步的 `tool/result` 之后），绝不会落在工具调用与其结果之间；如果最近的步骤边界会切在带 tool-call 的 assistant 消息之后，就往前挪一个步骤，实在没有安全边界时保留整轮，而不是把整轮清掉；
- 续接包（`【任务续接】…`，明确标注“不是新的用户请求”）包含当前请求、最近进展，以及按当前请求从本对话记忆库检索出的少量相关记忆（最多 3 条、约 1200 字符），让清出步骤后不用重新摸索项目规则；
- 同一次测量只重置一次：抑制键包含实测的 prompt 大小，只有新请求带回了新的测量值才允许下一次重置；剩下的步骤不足 3 个时不切割，直接把整个当前轮保留下来，避免反复清掉刚保留的内容；
- 一次替换覆盖整段窗口，因此不受之前任何一次清理造成的碎片影响；以前按轮拆分时，一次局部清理会让旧轮次永远不再连续，于是每次只清得掉一轮，占用一直下不来；
- 这一轮已经结束、没有下一次模型请求时，在 `turn/end` 走同一条路径：保留最近 `keepRecentTurns` 轮，其余全部清出；
- 硬重置不受 `minClearChars`、`maxClearTurns` 的裁剪限制，避免 60%+ 的窗口只清掉一小段；
- 清出后的便条仍是模型可见的 `user/message`，但带上 `source.kind = ai-for-memory`、`source.form = notice` 和 `source.summary`；真实用户输入的 `source.kind = user`，据此可区分两者；
- 手动 `clear` 仍按话题相似度选择，不会强制全清。

`topicalClear=false` 时，手动/每轮触发先保存上下文，再走 DSH 原生压缩；上下文占用阈值仍走全量重置。

### 自动快照

`autoSnapshot` 默认**开启**，与自动整理互相独立。

- 每 `autoSnapshotEvery` 轮（默认 5）保存最近上下文窗口；
- 最多保留 `autoSnapshotMax` 个（默认 10）；
- 超限时优先删除相似的旧自动快照；
- **只剪枝自动快照**，手动快照不会被自动删除。

### 请求锚点

`requestAnchor` 默认开启。它只在**每轮的第一步**、最新输入是系统检查点（`Time sampled...`、工具 schema 更新、插件重载提示等）、并且本步进入模型的 `payload.messages` 里没有新的真实用户请求时，追加一条很短的内部提醒，重申上一轮真实用户请求。

第二及之后的工具步骤不会再注入：这些步骤的 `payload.messages` 只有工具结果，本来就不含用户文本，按“没有新请求”判断会把锚点插进正在进行的轮次里；窗口里从此多出一条“当前请求是 X”的 user 消息，模型随后更容易继续回答 X 而不是最新输入。

锚点只重申仍在窗口里的请求：已经被清出的请求不会被重新写回成 user 消息（那等于把旧任务重新塞回上下文）。锚点文案明确是“上一轮请求参考”，如果之后出现新的用户输入，以新输入为准。检查点和新请求同轮到达时不会注入锚点。

它不会在每个正常请求前重复注入，所以不会变成常驻记忆开销；关闭它可以完全移除这段行为。

### 恢复

`aim_context restore` 不会把整份存档重新灌回上下文：

- 有 `raw_events` 时优先渲染原始事件，包含 `tool/call` 参数、`developer/message` 和工具结果；
- 按 `restoreMaxChars` 从**最新一行往旧**累计；预算不够时保留尾部，而不是截掉尾部；
- 恢复标题会写明「按 N 字符预算恢复最近 M/K 段」或「最近 M/K 轮」，能直接看出尾部/早期内容被省略；
- 单个工具结果在恢复文本中最多渲染 8 KiB，超出会带「工具结果已截断」标记；磁盘上的 `raw_events` 仍保留原始数据，后续仍可读取；
- 没有 `raw_events` 的旧存档退回 `turns`/`text`，同样从尾部选择。

### 保留策略

- `stagingRetentionDays` 默认 30 天：只删除“整份都已归档”的旧过程记录文件，未归档内容永不因保留策略丢失；
- `contextRetentionDays` 默认 0：不自动删除上下文存档，因为它是 restore 的来源；
- `decisionRetentionDays` 默认 0：不自动删除决策审计。

保留策略**不依赖自动整理开关**：每个对话每天第一次 `turn/end` 时检查一次；即使自动整理关闭，staging 的 30 天清理也会执行。归档操作本身不再重复重建全量去重集合，分类文件的去重集合按文件签名增量维护。
