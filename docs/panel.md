# 面板导览

> 返回 [主 README](../README.md)。

侧栏「AI 记忆」打开面板。面板采用工业软件式三段布局：

- **左侧导航**：总览、六层记忆数据、插件设置、诊断；
- **顶部工具栏**：当前范围（本对话 / 指定对话 / 全部对话 / 共享层）、工作区、对话、记忆目录、刷新；
- **主内容区**：总览卡片、当前层的列表/详情，或独立的插件设置页。

## 总览

总览是仪表盘而不是单纯的层列表：顶部有本地状态标签和知识库检索入口（回车直接进入过滤后的知识库），下面显示过程记录 / 知识库 / 上下文占用三张主卡片、记忆目录、知识存储、RAG（含知识库总数、语义去重和超上限未索引的拆分）、网络同步、清理阈值、当前对话、最近过程记录和上下文自动行为说明；点击任一记忆层可直接进入对应页面。

总览中间还有**会话日志修复**卡片：打开页面只做快速扫描（只读文件头，不解压整份日志）；需要结论时点「深度体检」，它会明确地异步解压并校验帧和事件，有损坏或异常膨胀时卡片变红并提示「上次会话可能未正常关闭，建议先恢复上下文存档」。修复/重排帧采用两步确认，截断策略会在确认按钮上写明将丢弃多少条事件；也可以跳到诊断页看完整列表和校验器来源。

## 设置页（插件内部）

设置不再堆在面板底部，也不再跳转 DSH 设置页。点击左侧「设置」进入插件自己的设置页，分为：

| 分组 | 内容 |
|---|---|
| 常规与上下文 | 记忆目录、目录名、自动整理、自动快照、RAG 挂载、MCP 出口、上下文清理、SQL 镜像、默认开放 |
| 模型与检索 | 外部模型、本地模型目录、Embedding/Rerank 两栏模型、连接测试 |
| llama.cpp | 本地引擎运行方式（常闭 / 常开 / 每轮开关）、选择模型并调 ctx-size、端口、pooling、启动超时、binary、extraArgs，保存后启动/停止 |
| 网络同步 | Git 同步开关、角色、remote、同步内容、初始化/提交/推送/拉取/探测 |
| 当前对话 | 对话名称、是否对其他对话开放；只对当前选中的对话生效 |

设置页保存后自动重载插件并刷新，不需要手动重载。

## 知识页

- **筛选**：分类、来源、确认状态；搜索框仍做子串匹配；
- **排序**：更新时间、置信度、命中次数、当前权重；
- **批量确认**：勾选当前筛选结果后可一次确认，不必逐条点；
- **命中信息**：每行显示命中次数和 14 天半衰期权重；权重 0 的条目是候选死条目；
- **截断提示**：`/state` 最多返回最新 200 条知识，页面会显示「当前显示 x/总数」和「只加载最新 200 条」，不会让分页看起来像丢数据；
- **撤销确认**：确认过的模型自述可撤销，恢复原 source / 未确认状态；知识正文和 doc_id 不变。

危险操作有二次确认：清理上下文、停止本地引擎、保留清理、删除知识。确认入口会明确写出影响范围。

## 诊断页

左侧「诊断」不再把运行信息散落在设置和 `/state` 中：

- **运行环境**：Node 版本、`node:sqlite` 是否可用、Git、`llama-server` 实际路径、`$DSH_HOME/ai-for-memory/models` 路径、记忆目录是否可写、gitignore 状态、总磁盘占用；
- **知识命中与权重**：每条知识的命中次数、最近使用时间、当前 14 天半衰期权重；权重 0 的「从未命中」条目排在最前，便于清理死条目；
- **对话占用与批量管理**：每个对话的磁盘占用和开放状态，勾选后一次开放或关闭；
- **会话日志体检与修复**：DSH 自己 `sessions` 目录下的全部日志，显示物理/逻辑大小、事件数、结构状态和异常膨胀标记；默认只做快速扫描，深度体检需要显式点击，解压使用异步 zstd 并按 mtime+size 缓存结果；修复/重排帧采用两步确认，截断前明确显示将丢弃的事件数，并显示实际使用的是 DSH 内置校验器还是本地回退校验器，修复前自动备份，当前对话不允许就地改写；
- **操作审计**：确认、删除、清理、恢复、保存配置、批量开放等面板操作的最近记录；
- **快照对比**：选择两个快照并排查看完整 `state`。

知识、上下文和快照条目在列表里可以直接「打开 JSON」或「下载全文」，不必先打开记忆目录再自己找文件。

## 顶部

- **查看范围**：本对话 / 指定对话 / 全部对话 / 共享层；
- 指定对话时，出现“工作区 → 对话”两级下拉；
- **记忆目录**：切换已登记的根目录；
- 刷新、复制路径、在文件管理器中打开。

工作区分组来自 DSH 的会话分桶，不使用对话中途的 `cwd`；Windows 和 POSIX 路径都会被正确识别，不会出现 `\tmp\...` 这种伪路径。

## 六个记忆层

| 页面 | 内容 |
|---|---|
| 过程记录 | 类型、来源、风险、验证状态、时间、正文 |
| 归档 | 按分类分组，可折叠 |
| 快照 | id、大小、时间、状态 JSON；可点「恢复」读取状态，或选两个快照「对比」 |
| 知识库 | 服务端混合检索、SQL 查询、分类、来源、标签、证据数、黄标、「确认这条」、删除、旧版本待确认更新的接受/拒绝、最近知识冲突（只读审计）、导出 |
| 决策 | 分「常规」与「风险」两栏：常规是每轮工具调用与文件改动的自动记录（outcome=observed），风险是 `aim_decide` 的正反合审查结论、风险、决策与正反理由 |
| 上下文 | id、标签、时间、轮次范围、字符数、摘要和全文；可保存、清理、恢复到当前对话 |

知识库里的「确认这条」就是模型自述的转正入口：确认后保留原 `doc_id` 和证据链，只把 `verified` 置为 `true`。删除按钮需要点两次确认，删除会同时清理该条知识的检索使用记录和提炼账本。旧版本入队的待确认更新仍会显示 target、正文、原因、冲突和出现次数，可直接「接受并写入」（等价于 `remember` + `confirm=true`，会覆盖目标正文）或「拒绝」；新提炼不再入队。被冲突闸门拦下的写入另外记在 `knowledge/conflicts.jsonl`，知识页顶部显示最近 5 条与未确认数（已确认的会标出来），只读、不提供应用按钮——它不是队列，只是让模型没转述时你仍能看到。

知识库顶部的检索框调用真实 `/search` 路由（BM25 + 哈希向量 + SQL/混合路由 + 可选 RAG），不是前端子串过滤；SQL 框可执行只读 `SELECT`，表名是 `knowledge_docs`。知识页的「立即操作」可手写过程记录、事实、快照、提炼、归档和事故。

上下文页的「保存当前上下文」「清理上下文」和每条存档的「恢复到当前对话」都直接走 API；清理需要点两次确认。每行还可以「导出 Markdown」，把 context 存档变成可直接阅读的文件。快照的「恢复」返回保存时的 JSON，不会假装注入在线对话；「对比」并排查看两个快照的完整 state。

模型页的本地引擎行现在同时提供「启动引擎并填入」和「停止引擎」；外部模型调试区可直接执行 `models` / `probe` / `chat` / `embed` / `rerank`。

模型页顶部固定为 **Embedding 模型** 和 **Rerank 模型** 两栏，Loose 根目录 GGUF 也会按类型归入对应栏；每栏可直接看运行状态、改 ctx-size、启动/停止。独立「llama.cpp」设置页提供本地引擎运行方式（常闭 / 常开 / 每轮开关）与完整调参（ctx-size、端口、pooling、启动超时、binary、extraArgs），保存写回 `model.json` 或根目录 `.model-meta.json`，再点启动生效。
