# 检索与 RAG

> 返回 [主 README](../README.md)。

## 检索是怎么工作的

### 本地检索

不需要任何外部服务，默认就能用：

- BM25 关键词检索；
- 128 维哈希向量；
- 两者用排名融合（RRF），不再做 min-max 分数线性相加。

倒排索引和文档向量有三层本地缓存，全部是 LRU：逐文档 tokens/向量按 `doc_id/updated_at/revision` 缓存（没有 revision 的旧文档退回哈希正文，同一毫秒内的同长度改写也会换 key）；倒排索引保留每篇文档的 postings 快照，写一篇只移除并重加这一篇，不再每次重建整张倒排；库级向量表同样按文档增量更新。缓存键是 `(库根, 分类)`，不同 MemoryStore 或分类各用各的索引。这是内部性能实现，不暴露为工具参数；`cacheMode` 仅供内部/测试（`document` 只跳过库级向量表）。默认结果只返回查询附近的摘要和全文长度，避免一次把整篇知识倒进上下文；需要全文时显式传 `detail: "full"`。

适合离线、隐私敏感、没有模型服务的项目。

### SQL 通道

问计数、分组、最近 N 条、标签、置信度、最长文档、未确认模型自述、精确 id 时，插件会把 JSON 文档装进一个临时只读 SQLite 库，翻译成单条 `SELECT` / `WITH`。

- 不允许写操作；
- 最多返回 50 行；
- 不需要打开持久 SQLite 镜像；
- 临时库按文档集合缓存，文档没变时复用；
- 临时表和持久镜像使用同一套语义列；
- 跨对话时，同一个 `doc_id` 会保留每个来源各一行：`COUNT(*)` 是副本数，`COUNT(DISTINCT doc_id)` 是不同事实数；
- 只有“最多 / 最少”但没有分类、来源等聚合对象的问题，会走向量，不会硬答一个无关统计。

### RAG

RAG 是知识库上的可选索引，不是默认检索。启用前需要同时配置：

- Embedding 模型；
- Rerank 模型。

打开「RAG 挂载」后，检索会同时跑 RAG 语义通道和本地 BM25 通道，再做排名融合：

- RAG 默认只索引最新 `maxDocs=500` 篇知识；manifest 会记录 `considered`（知识库总数）、`truncated`（超过上限、未参与索引）和 `deduped`（同分类余弦 ≥0.95 被语义去重的篇数），面板会分别显示，不再把“500 上限”和“语义去重”混成一个索引数；
- 只在 RAG 索引里被语义去重掉的旧文档，仍由 BM25 通道带回；
- 结果里会标 `RRF=...｜RAG#n｜BM25#m`；
- 先按分类过滤、嵌入召回，再 rerank；
- 重排服务不可用或返回异常时，明确回退本地检索；
- 各通道先做排名融合；置信度和「未确认」降权在 RRF 之后重新施加，避免纯排名把精细信号吃掉；
- 分片索引按 manifest 的内容哈希缓存（manifest 里带 `built_at` 和全部分片 hash，分片只在内容变化时重写），同一代索引不会在每次检索时重新解析所有分片；不用文件 mtime，避免粗粒度文件系统时钟把两次重建看成同一代；
- 建索引的跨进程写锁是异步等待，不会用 `Atomics.wait` 冻结 Node 事件循环；写锁文件带 pid，写入进程已死亡时会在短延迟后回收。
